# Обзор администратора Standard

Начальный экран `/admin` получает реальные показатели из D1 через `GET /api/overview`. Демонстрационный график, вымышленные проценты роста и константные счётчики удалены. Lite не получает базу или этот экран: API возвращает 404.

## Что считается

Период — последние 24 часа, 7 или 30 дней (по умолчанию 30). Это скользящий диапазон `[from, to)`, а не календарные сутки. Ответ фиксирует обе границы в миллисекундах; интерфейс показывает время обновления в часовом поясе устройства.

| Показатель | Правило |
| --- | --- |
| Новые клиенты | Созданные за период пользователи с ролью `customer` |
| Активные диалоги | Уникальные диалоги с сохранённым сообщением клиента/гостя за период; диалоги администратора исключены, demo-ответы учитываются |
| Новые заказы | Созданные за период заказы, включая отменённые |
| Новые бронирования | Созданные за период бронирования, независимо от даты услуги и статуса |
| Новые обращения | Созданные за период обращения, включая закрытые |

«Текущие задачи» не ограничены выбранным периодом: все заказы `pending`, все открытые обращения, записи на ближайшие семь дней. Для записей исключены прошлые, отменённые и просроченные платёжные резервы, включая старый формат `confirmed` с ожидающей оплатой. Последние обращения — до пяти за всё время, только тема, статус, идентификатор и дата создания.

Это операционные показатели, не посещаемость, не финансовая отчётность и не доказательство получения денег. Для источников, кликов и путей посетителей используйте отдельную [аналитику](ANALYTICS.md). Обзор использует существующие бизнес-записи и не включает сбор поведенческих событий.

## Доступ и эксплуатация

- Только действующая браузерная сессия администратора/владельца. Клиент, аноним, bearer-токен и межсайтовый запрос не получают обзор. Отдельного MCP-инструмента нет.
- Строгий параметр `period=24h|7d|30d`: повторы, неизвестные параметры и другие значения дают 400.
- До 10 чтений в минутное окно на администратора, затем 429. Нет фонового опроса; данные обновляются при открытии, смене периода и по кнопке.
- Ответ приватный, `Cache-Control: private, no-store`. Полные тексты диалогов и контакты клиентов в ответ не включены. Темы обращений всё равно могут содержать персональные данные и доступны только администратору.
- Один D1 batch с двумя запросами: агрегаты и последние обращения. Ошибка D1 даёт 503, интерфейс предлагает повторить загрузку, а не показывает фиктивные нули. Ожидание ограничено 20 секундами; поздний ответ прежнего периода не подменяет новый.
- Точные счётчики могут сканировать большие таблицы. Лимит запросов не является денежным потолком D1; перед крупной установкой нужна нагрузочная проверка и, при необходимости, агрегаты/дополнительные индексы.
- Новых миграций, зависимостей и секретов нет. Standard должен иметь все существующие миграции до 0018 включительно. Потребуется сборка и развёртывание обновлённого Worker; одной замены конфигурации недостаточно.

## Проверки

`npm test` проверяет диапазоны и строгие параметры. `npm run test:integration` проверяет доступ, реальные счётчики, неоплаченные резервы, отказ D1, квоту и OpenAPI. `npm run test:acceptance` проверяет пустую установку и показатели после восстановления backup. `npm run test:lite` проверяет недоступность API без D1.

Проверки выполняются только на изолированных тестовых данных. Облачная и нагрузочная приёмка остаются отдельными задачами.
