# Анализ сохранённых файлов в Standard

В чате можно загрузить новый файл скрепкой или выбрать собственный через «Мои файлы». Перед каждым анализом пользователь отдельно подтверждает передачу выбранному провайдеру. Обычная загрузка в R2 не вызывает AI.

Поддерживаются UTF-8 TXT/MD до 64 КБ через OpenAI/xAI. PNG/JPEG/WebP/PDF до 2 МБ — через OpenAI и модель с соответствующей поддержкой vision. Поддержка конкретной модели проверяется провайдером; движок не меняет модель автоматически. Исходная сигнатура файла не является проверкой его семантической корректности или антивирусной проверкой.

## Квота контекста

Все обращения идут через общую [квоту AI](AI-QUOTAS.md). В `AI_MAX_INPUT_BYTES` входят системный контекст, история и сериализованное вложение, включая base64. По умолчанию сохраняется 131072 байта: не каждый файл, допустимый для хранения, помещается в AI-запрос. При превышении возвращается 413 до обращения к провайдеру; молчаливого обрезания нет.

Владелец может явно повысить `AI_MAX_INPUT_BYTES` (теперь до 4 000 000). Например, 3 000 000 обычно вмещает base64 одного файла 2 МиБ и небольшой текстовый контекст. Это не гарантия токенной ёмкости модели и не денежный бюджет. Размер PDF в байтах не ограничивает число его страниц или стоимость их обработки.

## Приватность и история

- Анализ доступен только по браузерной сессии и только для собственного файла. Административное право просмотра чужих файлов не даёт права отправлять их провайдеру через этот механизм.
- Привязать файл можно только к своему диалогу. Главный чат теперь загружает собственные диалоги даже для администратора, используя `scope=mine`.
- Перед вызовом проверяются владелец, состояние загрузки, наличие объекта, размер, SHA-256 и формат. Нет публичных R2 URL, скачивания произвольных внешних URL или Files API загрузок провайдеру: байты передаются inline.
- При смене провайдера после подтверждения сервер отвечает 409; нужно подтвердить передачу заново. При выключенном AI нет фиктивного «анализа» в demo-режиме.
- Успешная пара сообщений и `messages.file_id` записываются одной транзакцией. В D1 не копируются base64 или текст исходного файла. Ответ модели, однако, может содержать выдержки из него.
- На следующих ходах файл автоматически не пересылается. Модель получает прошлые текстовые сообщения, ответы и пометку, что прежнее вложение сейчас не передано. Для повторного чтения нужно выбрать файл и подтвердить отправку снова.
- История возвращает безопасные метаданные и авторизованную ссылку скачивания, без ключа объекта или хеша. Для Bearer-чтения метаданных дополнительно нужен `files:read`; платный чат через Bearer/MCP не открывается.
- После удаления объекта из R2 ссылка в истории становится недоступной. Удаление не стирает старые ответы консультанта и не отзывает уже отправленные провайдеру данные. Уже начатый анализ может завершиться: транзакции между D1, R2 и AI не существует.
- Ошибка провайдера или записи сохраняет файл в кабинете, но не создаёт успешной пары сообщений. Повтор с прежним Idempotency-Key не запускает AI заново; новый ключ означает новую попытку. После сетевого сбоя сохраняйте ключ и исходное тело. [Гарантии и неизвестный исход](CHAT-RELIABILITY.md).

## API и обновление

`GET /api/chat` по сессии возвращает `provider`, `fileAnalysisEnabled`, `maxInputBytes`. В `POST /api/chat`:

```json
{
  "message": "Что указано в документе?",
  "fileId": "ID ранее загруженного собственного файла",
  "confirmFile": true,
  "fileProvider": "openai"
}
```

Обязателен заголовок `Idempotency-Key` (случайный ключ на ход, тот же при повторе). Для продолжения передайте `conversationId`. Допускается одно вложение на сообщение. Неизвестные поля, сырые вложения и URL вместо fileId отвергаются. Точный контракт — `/api/openapi`. Для новой защиты повторов также применяется миграция 0016, см. [обновление контракта](CHAT-RELIABILITY.md).

Перед обновлением Standard примените ожидающие миграции, включая `0015_sweet_nebula.sql`, обычным процессом с резервной копией. Добавляются nullable FK `messages.file_id` и индекс истории `idx_messages_conversation_created`; старые сообщения сохраняются без вложения. Сборка проверена с миграцией только в изолированных данных. Lite не требует миграций и сохраняет прежний stateless-режим.

## Проверки и исправление совместимости

Сквозной тест запускает собранный Worker с изолированными D1/R2 и перехватом исходящих запросов. Проверены успешная передача текста, форма image/PDF, привязка и чтение истории, чужой файл, согласие/смена провайдера, отключение AI, подмена R2, удаление, превышение квоты, отказ провайдера и атомарный откат записи. Реальные оплачиваемые запросы, качество распознавания и облачная/визуальная приёмка не выполнялись.

Этот тест также выявил несовместимый с Workers `redirect: 'error'` в AI-адаптере. Для текста/списка моделей и Realtime теперь используется `manual` с отклонением неуспешного ответа; перенаправления не выполняются и ключи не пересылаются другому хосту.

Формат inline-вложений сверен с [OpenAI Docs: изображения](https://developers.openai.com/api/docs/guides/images-vision) и [OpenAI Docs: файлы](https://developers.openai.com/api/docs/guides/file-inputs).
