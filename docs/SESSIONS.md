# Управление активными сессиями Standard

В `/account/profile` появился блок «Активные сессии» для клиентов, администраторов и владельца. Он показывает только сессии вошедшего пользователя: текущую первой, затем новые входы. Даты создания и истечения показаны в часовом поясе устройства. Это сессии входа, не список устройств: IP, User-Agent и время последней активности не собираются.

Можно завершить одну из других сессий своего аккаунта или все остальные. Требуются текущий пароль и явное подтверждение. Текущая сессия остаётся; для неё используется обычная кнопка выхода. При смене профиля список обновляется вместе с его версией, чтобы не оставлять старый идентификатор после ротации cookie.

## API

- `GET /api/auth/sessions` → `{ sessions: [{ id, createdAt, expiresAt, current }], truncated }`. Даты — миллисекунды Unix. Не более 100 активных сессий; если их больше, `truncated=true`. Текущая всегда первая. В ответе нет токенов, хешей, контактов или чужих сессий.
- `DELETE /api/auth/sessions`, JSON `{ target, currentPassword, confirm: true }` → `{ revoked: number }`. `target` — UUID сессии или `others`. Неизвестный, чужой и уже отозванный UUID одинаково возвращают `revoked:0`, без раскрытия владельца.
- Только браузерная cookie; bearer-токены и MCP не управляют сессиями. Заголовок Authorization не может использовать права cookie. Неизвестные роли, URL-параметры, лишние поля и межсайтовые запросы запрещены.
- Чтение: до 30 запросов/минутное окно на пользователя. Отзыв: до 10 попыток/15-минутное окно, включая неверный пароль; потом 429. DELETE ограничен JSON-телом 2048 байт, пароль — до 256 символов.
- Ответы не кешируются. Ошибка D1 возвращает 503, а не успешный выход. Пароль в состоянии формы очищается после попытки или закрытия окна; не помещается в browser storage и не логируется.

## Конкуренция и границы безопасности

Удаление ограничено пользователем, сроком действия и исключением текущего ID. В одной D1 batch-транзакции повторно проверяются исходная сессия и неизменность хеша пароля. Отозванная сессия или параллельная смена пароля не должны разрешить запоздалый DELETE. Одновременные повторы отзыва одного UUID удаляют максимум одну строку. После неопределённого сетевого результата сначала обновите список.

Завершение входа не отменяет уже начатые операции и не блокирует будущий вход с действующим паролем. В список не входят истёкшие сессии; фоновая очистка их строк здесь не реализована. API-токены агентов не отзываются: ими управляют отдельно в разделе AI-агентов. Это не восстановление забытого пароля, не MFA, не антивзлом и не полный аудит активности.

## Обновление

Для Standard примените новую аддитивную миграцию `0019_flowery_christian_walker.sql` и разверните обновлённый Worker. Она добавляет только индекс `idx_sessions_user_expiry(user_id, expires_at)` для выборки сессий пользователя. Старая история миграций сохранена; новых полей, зависимостей и секретов нет. Lite не требует миграции, API в нём возвращает 404.

## Проверки

`npm test` проверяет формат подтверждения и ограничения. `npm run test:integration` — изоляцию владельцев, защищённый список, пароль, текущую сессию, повтор/конкуренцию, ошибку D1, массовый отзыв, лимиты и OpenAPI. План выборки подтверждает использование нового индекса на тестовой базе. `npm run test:lite` подтверждает отсутствие доступа без хранилища; `npm run test:acceptance` проверяет установку и восстановление всех миграций.

Реальные пользовательские сессии для проверки не используются. Облачная приёмка и проверка физических мобильных устройств остаются отдельными задачами.
