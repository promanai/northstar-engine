# OpenAI и xAI

Standard теперь использует [общую квоту AI](AI-QUOTAS.md): по умолчанию 100 попыток в день, 1000 в месяц, потолок ответа 4096 токенов. Потолки задаются владельцем в Worker; остатки видны в разделе «Модели». Нужна новая аддитивная миграция 0014. Это квота попыток, не денежный бюджет.

Движок использует серверный Responses API двух провайдеров. SDK не нужен: адаптер работает через fetch в Cloudflare Workers. Настройки — `/admin#models` → «Модели».

## Подключение

1. Получите API-ключ у выбранного провайдера в собственном аккаунте. Подписка на ChatGPT/Grok и API-доступ — отдельные продукты.
2. В Cloudflare откройте свой Worker → Settings → Variables and Secrets. Добавьте секрет `OPENAI_API_KEY` и/или `XAI_API_KEY`. Не используйте публичные vars, настройки сайта, каталог, инструкции консультанта или исходный код для ключей.
3. Для локальной разработки задайте эти значения в игнорируемом `.env` или `.env.local` в корне проекта (образец — `.env.example`), затем перезапустите локальный сервер. `npm run start` явно передаёт абсолютные пути этих файлов Wrangler; не кладите ключи в `dist`, который заменяется при сборке. Файлы секретов не входят в release-пакет.
4. В админке нажмите «Перезагрузить настройки», затем «Проверить ключ и загрузить модели». Получение списка не вызывает генерацию; оно не гарантирует доступ к каждой модели и её совместимость с текстовым Responses API.
5. Для задач «Консультант» и «Генерация текстов» выберите провайдера и модель из списка либо введите ID вручную. Модели-подсказки не являются гарантией доступности в вашем аккаунте.
6. При необходимости настройте рассуждение, лимит выходных токенов (128–32768), ожидание (10–120 секунд), температуру там, где она поддерживается. «По умолчанию» не отправляет соответствующий параметр провайдеру. Лимит выходных токенов включает невидимые reasoning tokens; слишком маленького лимита может не хватить даже на начало ответа.
7. «Проверить ответ · платный запрос» вызывает модель с текущими полями, без сохранения. Это реальный тарифицируемый запрос. Проверка не посылает каталог или историю клиентов. После успешной проверки включите нужную задачу и сохраните настройки.

Сохранение настроек не запускает генерацию и не требует пересборки. Параллельное сохранение старой версии получает 409: перезагрузите настройки, сверьте правки и повторите. Обновление ключа требует применения секрета к Worker; ключ в D1 не записывается.

## Поведение

- Консультант использует выбранный провайдер, системный контекст, активный каталог и последние 20 сообщений доступного пользователю диалога. Успешный ответ записывается атомарно с вопросом. Модель сообщения отмечается как `openai/<model>` или `xai/<model>`.
- До первого сохранения нового раздела сохраняется прежняя настройка: наличие `OPENAI_API_KEY`, `assistant_profiles.active_model`, затем `OPENAI_MODEL`, затем `gpt-4o-mini`. После сохранения приоритет полностью у `ai_settings`; старое поле `activeModel` в REST/MCP больше не выбирает модель. Контекст и статус ассистента по-прежнему управляются через `/api/assistant` и MCP.
- Выключенный консультант работает в явном demo-режиме. Если включённый провайдер потерял ключ, отклонил запрос, превысил таймаут или вернул незавершённый ответ, возвращается ошибка без demo-подмены и без сохранения пары сообщений.
- Автоматического повторения платных запросов и переключения на другого провайдера нет. Частичный ответ не выдаётся за завершённый; повтор пользователем может тарифицироваться отдельно.
- Генерация текстов использует отдельную сохранённую модель. Можно подготовить описание услуги или текст страницы в админке, но публикации/изменения CMS автоматически не происходит. Результат генератора остаётся в текущем экране и не сохраняется в D1.
- Список поддержанных уровней задаётся консервативной матрицей в `lib/ai-policy.ts`. Сейчас явное рассуждение поддерживается для GPT-6 Astra, GPT-5.6 Luna, Grok 4.6 и Grok 4.5 (включая распознаваемые датированные ID). Температура доступна для обычных GPT-4o/GPT-4.1. Другие ID разрешены с параметрами по умолчанию; расширять матрицу следует после проверки документации модели.
- Параметр `store:false` отключает сохранение Responses для дальнейшего получения через API; это не обещание нулевого хранения всех данных у провайдера. Не помещайте пароли и секреты в промпт или внутренние инструкции товара. Инструкция «не раскрывай» не является границей доступа.

## API

Полный контракт: `/api/openapi`, путь `/ai`. Требуется браузерная сессия owner/admin; Bearer/MCP токены, в том числе `*`, не принимаются на этом endpoint. Клиенты не могут менять маршрут, параметры, системный контекст или ключ в запросе `/api/chat`.

`GET /api/ai` — конфигурация, revision, источник настроек и только boolean-признаки наличия ключей. `POST /api/ai` принимает:

```json
{ "action": "models", "provider": "xai" }
```

```json
{ "action": "generate", "task": "text", "prompt": "Напишите описание по этим фактам…", "confirmPaid": true }
```

Для `save` передайте `config` с полными профилями `chat` и `text`, плюс прочитанную `revision`. Для `test` — полный `profile` и `confirmPaid:true`. Формат профиля смотрите в OpenAPI. Общий лимит административных действий — 20/минуту на администратора; тест/генерация дополнительно ограничены 5/минуту. Это не денежный бюджет: ограничьте расходы и в кабинете провайдера.

## Установка и границы готовности

Новая аддитивная миграция `0006_common_black_tom.sql` создаёт `ai_settings`. На отслеживаемой установке примените ожидающие миграции обычным способом перед обновлением Worker. Не повторяйте старые миграции вручную на заполненной базе. Никаких ключей или тестовых записей миграция не создаёт.

Работают текстовый консультант, генератор текстов и [подтверждаемый анализ собственных R2-вложений](CHAT-FILES.md). Транскрибация, realtime в Standard, streaming, инструменты заказа в чате, денежный бюджет расходов и полное управление настройками моделей через MCP остаются отдельными задачами. Для анализа изображений/PDF нужна подходящая OpenAI-модель; выбор неизвестной модели не гарантирует поддержку vision.

Адаптер проверяется unit-тестами с подставным fetch: оба origins, payload, рассуждение, ошибки, таймаут, ограничение размера, выделение только публичного текста и usage. Интеграционные тесты проверяют авторизацию, D1, конкурентное сохранение и отсутствие ключей на отдельном Worker. Реальный оплачиваемый запрос и production-доступность требуют ключа владельца и проверки в его установке.
