# Версионные настройки сайта

В Standard раздел **Админка → Дизайн → Сайт и оформление** управляет названием,
описанием главной страницы, языком контента, темой и фоновым изображением.
Пять полей сохраняются одним действием с подтверждением. Предпросмотр темы
не публикует изменения. История показывает версию, время, автора и источник;
восстановление создаёт новую версию, не удаляя последующие события.

## Хранение и совместимость

- Используется существующий `documentStore`: документ `site-config` в D1,
  таблицы `site_documents` и `site_document_revisions` из миграции 0011.
  Новых таблиц, сервисов и привязок Cloudflare не добавлено.
- До первой записи известные старые значения читаются из `site_settings`:
  `public.siteName.text`, `public.description.text`, `public.locale.code`,
  `theme.template.id`, `public.backgroundImage.url`.
- Некорректное старое поле заменяется безопасным значением по умолчанию;
  редактор показывает предупреждение. Исходная старая строка не удаляется.
  Версия 0 содержит импортированную безопасную конфигурацию, а не сырые строки.
- Первая запись атомарно сохраняет версию 0, новые значения и событие.
  Ошибка журнала откатывает всю операцию; конкурентная запись получает 409.
- После первой записи источником истины становится документ. Старые значения
  не перезаписываются и не влияют на новые настройки.
- `/api/settings` сохраняет совместимую форму чтения известных полей.
  Для посетителя теперь возвращаются только пять известных публичных полей,
  а не любые ключи с префиксом `public.`. Форкам с дополнительными публичными
  настройками нужен собственный проверяемый API. Расширения администратору видны.
- Запись этих пяти ключей через старые `/api/settings` и MCP
  `site_update_settings` отклоняется: обход истории и revision закрыт.

## REST и MCP

`GET /api/site-config` — только публичный объект, без журнала и идентификаторов
авторов. `?view=admin` — `{revision, value, warnings}`.
`?view=history&before=N` — `{versions, nextBefore}`, до 50 событий за запрос.
Все ответы без кеширования. Приватное чтение требует owner/admin; токен также
должен иметь `site:read`.

`PUT /api/site-config` требует owner/admin, а для токена — `site:write`:

```json
{
  "revision": 3,
  "confirm": true,
  "value": {
    "name": "Моя компания",
    "description": "Консультации и услуги",
    "locale": "ru",
    "theme": "northstar",
    "backgroundImage": "/images/background.jpg"
  }
}
```

Нужно передать все пять полей. Откат: `{revision: 3, targetRevision: 0,
confirm: true}`; дополнительно требует `site:read`.
Неизвестные поля, неверные типы, слишком длинные строки, неподдерживаемая тема,
URL с логином/паролем, небезопасной схемой или обратными слешами отклоняются.
Ограничения: 8 КБ JSON, до 20 попыток записи в минуту на администратора, общий
лимит для REST и MCP. HTTP 409 нельзя слепо повторять: перечитать состояние,
сопоставить изменения, получить подтверждение.

MCP-инструменты `site_config_get`, `site_config_update`, `site_config_history`,
`site_config_restore` вызывают те же операции, используют те же ревизии и
записывают ID токена в журнал. Агент должен получить подтверждение пользователя
перед публикацией; само поле `confirm` не является доказательством согласия.
Контракт опубликован в `/api/openapi` и схемах MCP.

## Публичные экраны и границы

- Название используется в шапке, подвале и заголовке чата; название и описание —
  в метаданных главной. Тема и фон отдаются уже в серверной разметке.
- После сохранения обновляется текущая вкладка; другая вкладка получает
  настройки при возвращении фокуса. Это не постоянная push-синхронизация.
- `locale` (`ru`/`en`) — язык контента в метаданных, не перевод интерфейса или
  инструкции модели. Язык существующего русскоязычного интерфейса не меняется.
- Описание — одна строка до 320 символов. Тема — northstar/editorial/ocean.
  Внешний фон загружается браузером посетителя; сервер изображение не скачивает
  и не проверяет его доступность. Фон можно убрать пустой строкой.
- Секреты, AI-профили, настройки интеграций, код, каталоги и SEO отдельных
  страниц этим документом не управляются. Для них остаются свои операции.
- **Lite по-прежнему работает без D1/R2:** контент из `site.config.json`,
  административный API и редактор отключены. Контракт Lite не ужесточён.

## Проверка

Unit-проверки: формат полей, URL, импорт старых значений, разрешения MCP.
Standard-интеграция на отдельной D1: импорт и предупреждения, публичная
проекция, права/Origin/размер запроса, конкуренция, серверные метаданные,
единая история REST/MCP, откат и отказ журнала. Lite проверяется без хранилищ.
Облачная база не мигрировалась и облачный Worker в рамках этого шага не публиковался.
