# Управление страницами и версиями

Доступно в Standard. Lite по-прежнему читает site.config.json и не включает админку или D1.

## Общие операции

Редактор, REST и MCP используют lib/page-service.ts. Только owner/admin могут управлять страницами; неизвестные роли не получают административных прав. Bearer-токен дополнительно ограничен scopes. История требует pages:read, изменение — pages:write, восстановление — обоих разрешений.

Сохранение страницы и запись истории выполняются атомарно в D1 batch. Для существующей страницы PATCH и DELETE требуют текущую revision. При параллельном сохранении выигрывает только один запрос, второй получает 409; MCP возвращает isError. Не повторяйте изменение автоматически с новой revision: сначала прочитайте актуальное состояние и согласуйте конфликт.

Удаление требует confirm: true и переводит страницу в deleted. Она исчезает из публичного сайта, но остаётся в корзине с историей. Адрес остаётся занят. Физической очистки корзины в этой версии нет.

POST /api/pages/{id}/restore принимает revision, targetRevision и confirm: true. Восстановление всегда создаёт **новый черновик**, не публикует старый контент и не удаляет последующие версии. Версии удаления нельзя выбирать как источник восстановления.

GET /api/pages/{id}/history возвращает последние 50 записей и nextBefore для следующей страницы. История содержит автора, идентификатор токена (не его секрет), источник, действие и время. Снимки хранятся на сервере; endpoint истории отдаёт только метаданные.

MCP: list_pages, upsert_page, delete_page, page_history, restore_page. upsert_page без id создаёт страницу (нужны title и slug); с id обновляет существующую (нужна revision). DELETE без JSON-тела и старые агенты без revision больше не поддерживаются намеренно.

## Обновление существующей установки

Перед запуском нового Standard примените миграцию 0010_lazy_eternity.sql обычным процессом миграций к выбранной базе с предварительной резервной копией. Не применяйте её к Lite. Она добавляет revision/mutation_id и таблицу page_revisions, не удаляет данные.

Исходное состояние ранее созданной страницы сохраняется как baseline в одной транзакции с её первым изменением. До первого изменения история такой страницы пуста. Миграция автоматически в облаке не применялась.

Старые версии Worker не записывают журнал и не проверяют revision: не смешивайте старую и новую версии при постепенном выкатывании этого изменения. После начала новых записей откат на старый код требует отдельного решения по совместимости.

## Границы этого этапа

Версии и корзина реализованы для страниц, не для каталога, меню или всех настроек. Это основа, а не готовый встроенный админ-агент. Аудит внутри той же базы не защищён от администратора с прямым доступом к D1. Сохранение новых страниц пока не имеет отдельного idempotencyKey: после неопределённого сетевого сбоя сверяйте список страниц, а не создавайте дубликат. Автоматическая очистка истории и резервное копирование должны быть настроены отдельно.
