# Проверка стабильности Lite

## Исправленный сбой

На прежней локальной сборке последовательность на одном HTTP/1.1 соединении воспроизводила ошибку:

1. `POST /api/chat` → 200 (демонстрационный режим).
2. `PUT /api/settings` с `{}` → 404 (модуль отключён в Lite).
3. `POST /api/chat` → 500, `Network connection lost` от Miniflare.

Причина — общий ответ для отключённых модулей/неподдерживаемых методов возвращался без чтения тела запроса. Ошибка проявлялась на следующем запросе и выглядела как проблема чата. На старой сборке новый тест падал на третьем запросе; на исправленной проходит вся последовательность.

Перед такими ответами Lite теперь дочитывает отклонённое тело. Общий `discardBody` ограничен 64 КиБ и 2 секундами по умолчанию; данные не накапливаются. По достижении предела поток отменяется без ожидания зависшего источника, блокировка читателя освобождается. Повреждённая загрузка не заменяет первоначальный отказ неожиданной серверной ошибкой. Полностью прочитанный поток не отменяется.

Это не гарантия сохранения соединения при превышении лимита или обрыве клиентом. Для этих случаев обещается ограниченная работа обработчика, а не бесконечное чтение. Ограничение относится к дочитыванию отклонённых тел, не является общим таймаутом всех загрузок движка.

## Команды проверки

```sh
npm run build
npm test
npm run test:lite:stability
npm run test:integration
```

`test:lite:stability` выполняет **три независимых последовательных прогона**, без автоматических повторов упавшего прогона. Каждый запускает новый локальный Worker с отдельным тестовым состоянием, проверяет 12 сценариев Lite, а затем запускает 5 сценариев формы в Chromium на том же Worker. Первый сбой даёт ненулевой exit code и останавливает серию.

В каждом прогоне 60 HTTP-запросов выполняются через один keep-alive socket без переподключения: успешный чат, отключённые/неизвестные модули, POST/PUT/PATCH/DELETE, 405, межсайтовой отказ, тела с Content-Length и chunked, тело 32 КиБ и проверка следующего запроса. Отдельные unit-тесты проверяют EOF, лимит байтов, зависший/сломанный источник и освобождение читателя.

Быстрые отдельные команды сохранены: `test:lite` — API; `test:leads-browser` — браузер. CI использует `test:lite:stability`, то есть не заменяет API-тесты браузерными и не скрывает падения переподключениями.

JSON-отчёт создаётся в новой `.test-state-lite-stability-*/stability-report.json`: отпечаток сборки, время, коды завершения всех выполненных прогонов. Браузерные отчёты и скриншоты находятся в отдельных `.test-state-lite-*` каталогах; пути выводятся в терминал. Реальные черновики, токены и переписка не входят в эти отчёты. Оба типа отчётов включены в CI-артефакты.

## Границы доказательств

Проверки локальные, на синтетических данных. Lite не подключает D1/R2, платный AI и внешнего получателя заявок. В браузере подставляются ответы `/api/leads`; серверная отправка проверяется отдельно с подставным transport. Standard проверяется на собственной тестовой D1/R2, не на базе владельца.

Три успешных прогона не заменяют нагрузочную проверку или приёмку Cloudflare production. Нужны отдельные проверки домена, реального AI, согласий и получателя заявок. OraVera не публикуется и не изменяется этими командами.
