# Паспорт сборки

Каждый `npm run build` создаёт `dist/engine-build.json` и встраивает ту же метку в Worker. И Lite, и Standard возвращают её через `GET /api/health` с `Cache-Control: no-store`:

```json
{
  "format": 1,
  "id": "64 lowercase hex characters",
  "version": "0.4.0",
  "commit": null
}
```

Пример показывает структуру, а не пригодный для проверки идентификатор. В health объект находится в поле `build`; верхнее поле `version` совпадает с `build.version`. Дополнительно возвращаются `status`, `service`, `mode`, `storage`. Это liveness: маршрут не читает D1/R2 и не вызывает AI. `storage: d1` обозначает режим Standard, а не проверку доступности базы. Lite возвращает `storage: none`.

## Откуда берутся значения

- Версия: `ENGINE_BUILD_VERSION`, по умолчанию `0.4.0`. Это версия движка, не версия npm-пакета.
- Commit: полный SHA из `ENGINE_BUILD_SHA`, иначе `null`. Git не вызывается; незакоммиченные изменения входят в отпечаток исходников, но не меняют указанный оператором commit.
- ID: SHA-256 выбранных исходных файлов, метаданных версии/repository/commit, режима сборки и версии Node.js. Текстовые CRLF нормализуются в LF, имена сортируются, бинарные файлы хешируются как есть.
- Публичная метка содержит только format/id/version/commit. Имя репозитория, список файлов, миграционные хеши, пути и секреты не публикуются.

В отпечаток входят `app`, `components`, `lib`, `db`, `drizzle`, `hooks`, `public`, `scripts` и перечисленные в `scripts/build-stamp.mjs` корневые файлы приложения/сборки, включая lockfile и `site.config.json`. Скрытые файлы и вложенные `node_modules` пропускаются; символьные ссылки на выбранной поверхности запрещены. `.env`, `.wrangler`, тестовые состояния, отчёты, резервные копии, cookie и рабочие данные не обходятся. Не размещайте секреты в исходниках или public.

## Проверка

1. Соберите выпуск. Сохраните его паспорт вместе с артефактом **до следующей сборки**, которая перезапишет `dist/engine-build.json`.
2. Разверните выбранный артефакт обычным способом на явно выбранной установке.
3. Выполните `npm run check:standard -- --url https://YOUR-SITE.example --expect-build dist/engine-build.json --report outputs/after-update.json`. Каталог отчётов должен существовать, файл — быть новым.

Паспорт берётся из доверенной ожидаемой сборки, не скачивается с проверяемого сервера. Проверяется строгая схема, размер до 4 KiB; произвольные поля не переносятся в отчёт. Отчёт содержит ожидаемую метку и результат сравнения, не сырое тело health. Без флага явно возвращается `not_requested`. При несовпадении прогон останавливается до запросов с административной cookie. Административная проверка по-прежнему требует явного `--admin-origin` и секретной переменной окружения.

## Чего эта проверка не доказывает

Метка помогает обнаружить старую или не ту сборку на доверенном сервере. Это **не цифровая подпись, не хеш конечного bundle и не криптографическая аттестация**: сервер может скопировать метку. Не проверяются runtime-конфигурация/секреты, реальные установленные зависимости, D1/R2, журнал миграций, содержимое данных, резервные копии и успешность оплаты. Повторная сборка на другой версии Node или с другими build-параметрами может дать иной ID. Для dev/HMR метка рассчитывается при загрузке Vite-конфигурации; приёмку выполняйте на production build.

Новых ресурсов Cloudflare, зависимостей, миграций и платных вызовов для паспорта не требуется.
