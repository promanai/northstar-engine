# Личный AI-агент пациента — Standard / OraVera

## Подключение

1. Пациент регистрируется или входит через `/login`. Пароль остаётся в браузерном сценарии, а не передаётся внешнему агенту.
2. В `/account` раскрывает **Your AI agent**. Выбирает имя, срок 1/7/30 дней и **View only** либо **Manage my appointments**.
3. Проверяет права в диалоге и подтверждает выдачу. Токен показывается один раз; хранится только хеш SHA-256. Серверные ответы `no-store`, браузер не записывает секрет в localStorage/sessionStorage.
4. В доверенном MCP-клиенте указывает адрес своей установки `https://<site>/api/mcp` и секретный заголовок `Authorization: Bearer <token>`. Нужна поддержка произвольного заголовка; OAuth и автоматическое подключение пока не реализованы. Использовать HTTPS вне localhost.
5. Агент вызывает `initialize`, `tools/list`, затем разрешённые `tools/call`. Версия протокола текущего адаптера — `2025-03-26`, HTTP POST с JSON-ответами, без SSE.
6. Кнопка **Revoke** с подтверждением отзывает доступ для новых запросов. Выполняющийся запрос может завершиться. Если создание оборвалось и секрет не получен, сначала обновить список и отозвать лишнюю запись, затем повторить выдачу.

Токен нельзя помещать в URL, публичные промпты, отчёты или репозиторий. Закрытие раздела скрывает секрет, но не отзывает токен и не очищает системный буфер обмена. Вход/выход и отзыв токена — разные операции.

## Права

| Режим | Разрешено |
| --- | --- |
| View only | `content:read`, `catalog:read`, `bookings:read`: опубликованный контент, активный каталог, доступные слоты и собственные записи |
| Manage my appointments | Те же права + `bookings:write`: создание, перенос, отмена собственных записей и запрос платёжной ссылки |

`audience=patient` сохраняется в D1. Bearer-аутентификация всегда ограничивает такой токен ролью customer, даже если его выпустил owner/admin. Ограничение действует для REST и MCP. Токен не получает чужие записи, административную ленту событий, управление расписанием, страницами, клиентами, фото или настройки. Нельзя выдать следующий токен с помощью уже выданного токена.

`GET/POST/DELETE /api/patient-agent` требуют браузерную сессию. POST принимает только `name`, `access=read|book`, `expiresInDays=1..30` и `confirm=true`. GET возвращает последние 100 записей, без токенов/хешей, с `truncated`. DELETE принимает `?id=...`, требует same-origin и JSON; можно отозвать только свой токен с patient audience. Контракт есть в `/api/openapi`.

Создание токена не имеет межзапросной идемпотентности: UI блокирует повторный клик, но потерянный ответ требует проверки списка. Серверная квота — 10 попыток выдачи в час на пользователя, общая с `/api/tokens`; отзыв — 30/мин.

## Запись и оплата

Агент должен показать пациенту услугу, время с часовым поясом, цену и изменения до выполнения операции. Для создания использует `idempotencyKey`, а для reviewed offer — `expectedPrice`, `expectedCurrency`, `expectedSlotRevision`; для изменения — `revision`. Это не универсальный серверный prepare/confirm: обладатель write-токена технически может выполнить действие сразу. Не выдавать его недоверенному агенту.

`checkout_booking` выдаёт ссылку, когда настроен провайдер, но не списывает средства. Оплата завершается пациентом на размещённой платёжной форме; статус подтверждается серверным событием провайдера. Отмена не делает возврат автоматически. Реальных платёжных вызовов при реализации этого шага не было.

## Публичный контент для AI

- `/llms.txt` — название текущей установки, инструкция подключения, ссылки на опубликованные страницы.
- `/llms-full.txt` — инструкция + публичный текст страниц и первые 100 активных товаров/услуг.
- `/api/content?slug=/about`, `/about` с `Accept: text/markdown` и MCP `get_page_markdown` используют один reader в Standard.
- Главная читает актуальный публичный site config. Каталог берётся из D1, а не из демонстрационного JSON пресета.
- Для страницы D1 имеет приоритет над OraVera preset. Если её override — draft/trash, preset не публикуется взамен. Неизвестные и приватные пути через public reader дают 404.
- Markdown блоков содержит только отображаемые `text`/строковый `content`, заголовки, списки и локальные CTA. Произвольные metadata и внутренние инструкции не сериализуются.
- HTML/Markdown различаются через `Vary: Accept`. Явное `text/markdown;q=0` не включает Markdown. Markdown и llms используют `no-store`, чтобы не оставлять ранее опубликованный текст в промежуточном кэше после снятия с публикации.
- Индекс ограничен 100 D1-страницами и явно сообщает об усечении. Известные опубликованные адреса вне индекса доступны через `/api/content`. Это информационная проекция, не полный экспорт базы и не единый реестр включённых возможностей.

Существующие owner-токены с `pages:read` сохраняют доступ к публичному Markdown. Черновики администратор читает через отдельные авторизованные page API, а не через публичный reader.

## Обновление и границы

Миграция `0021_lying_kitty_pryde.sql` добавляет только `api_tokens.audience NOT NULL DEFAULT 'account'`. Старые токены сохраняют прежнюю семантику; новые пациентские получают явное значение `patient`. Сначала сделать резервную копию выбранной D1, применить миграции, затем использовать новую сборку. Не подменять существующие миграции и не разворачивать новый auth поверх старой схемы.

Lite остаётся без D1, аккаунтов и выдачи этих токенов; его публичные статические маршруты продолжают обрабатываться существующим Lite router.

В Standard OraVera клинические chat/files/realtime/leads по-прежнему закрыты. Этот шаг не включает хранение медицинских фото, клинические ответы модели, настоящие платежи, Telegram-бота или облачный деплой. Для запуска нужны реальные данные клиники, утверждённые правила работы с пациентами и отдельная приёмка Cloudflare.

Проверки: `npm test`, `npm run test:integration`, `npm run test:oravera-account`, `npm run test:acceptance`. Новые сценарии в `tests/patient-agent-integration.mjs` запускаются набором OraVera с отдельной синтетической D1; реальная база пользователя не заполняется тестовыми записями.
